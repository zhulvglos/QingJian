新增 Supabase Auth REST 对接和 Postgres RPC/RLS，不新增 npm/Rust 依赖。下载依赖未获授权，本次用 D 盘既有依赖进行 `cargo --offline` 构建。检查路径及父目录未发现额外 AGENTS.md，按用户在聊天中提供的规则及本次明确授权执行。

同步账本仅安装在账号数据库，原未登录数据库不新增触发器。各账号的 SQLite、WebView、备份登记与本机设置独立；刷新令牌按项目/账号/数据根隔离保存于系统凭据存储。退出先阻止新的同步请求，再等待已发请求结束；没有把旧账号队列转交新账号。

第一版同步内容包括富文本、软删除/恢复、永久删除墓碑、置顶和排序。提醒、快捷标签、录音、模型密钥、新闻及设备设置不上云。**“已同步”不包含提醒**，新电脑需要重新设置提醒。首次复制内容不复制提醒，也不移动原本地内容。

## 免费条件与开通所需最少事项

选择 Supabase Free：500 MB 数据库、50,000 月活、5 GB 出站流量、最多 2 个活跃免费项目；闲置一周可能休眠；没有自动数据库备份。条件来源为 [Supabase 官方定价](https://supabase.com/pricing)，核查日为本报告日期。后台每 60 秒扫描版本索引，只下载变化正文；仍消耗请求与流量，不承诺无限永久免费。

默认发信只面向项目团队邮箱、2 封/小时，不能拿它承诺普通邮箱数字 OTP。Resend 的免费测试域存在收件人限制，Brevo 对发件人/域有要求；没有现成可用发件配置时不通过付费或购买域名绕过。最小试用优先尝试管理员已有的独立邮箱 SMTP，是否允许第三方云端发送、额度和 QQ 实收都需开通时验证。

下一步最少需要：

1. 用户确认创建 Supabase Free 项目及执行已提供的 SQL，不启用付费或绑定支付方式。
2. 管理员选择已有独立发件服务，在云端填写 SMTP 凭据及 `{{ .Token }}` 验证码模板；**不要把授权码或管理密钥发到聊天里**。
3. 在云端配置 OTP 300 秒、同邮箱重发间隔 60 秒、项目发信建议 10 封/小时、验证请求建议 5 次/5 分钟/IP，真实测试服务端限制。IP 请求窗口限制不等于每个验证码连续失败次数锁定。
4. 应用填写项目 URL 和公开 Publishable / anon key；用本人 QQ 测试邮箱收信并完成验证，先做合成内容的真实双客户端测试。
5. 用户另行授权后才上传真实便签或笔记。现在的真实数据快照只留在 D 盘。
